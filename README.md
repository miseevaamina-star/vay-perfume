# Подключение Supabase к VAY PERFUME — что сделать вручную

Всё это делается один раз, в браузере, без кода. Займёт минут 15–20.

## 1. Создать проект

1. Зайти на [supabase.com](https://supabase.com), зарегистрироваться / войти.
2. **New project** → название (например `vay-perfume`), задать пароль
   базы данных (сохраните его отдельно, он понадобится редко, но
   пригодится), выбрать регион (ближе к России — обычно Frankfurt).
3. Подождать 1–2 минуты, пока проект создастся.

## 2. Создать таблицы (schema.sql)

1. В левом меню: **SQL Editor** → **New query**.
2. Открыть файл `supabase/schema.sql` из этого архива, скопировать
   всё содержимое, вставить в редактор.
3. Нажать **Run**. Должно появиться "Success. No rows returned".

Это создаст таблицы `fragrances`, `reviews`, `faq` и настроит защиту
данных (RLS) — подробности в самом файле.

## 3. Создать хранилище для фото

1. Слева: **Storage** → **New bucket**.
2. Имя бакета: `fragrance-photos` (ровно так, с этим именем в коде).
3. **Public bucket** — включить (чтобы фото открывались на сайте
   напрямую по ссылке).
4. Создать.

Политики доступа к этому бакету (кто может читать/загружать) уже
описаны в конце `schema.sql` — они применились на шаге 2.

## 4. Перенести текущий каталог и отзывы (один раз)

1. Снова **SQL Editor** → **New query**.
2. Открыть `supabase/seed_import.sql`, скопировать всё, вставить, **Run**.

Это загрузит все 23 текущих аромата и 7 отзывов в базу с их реальными
названиями, ценами, нотами и текстами — ничего не придумано, взято
из `js/script.js`. Фото товаров при этом продолжат подгружаться из
папки `assets/` сайта (ссылки вида `assets/him-01.jpg`) — это
нормально работает и через Supabase. Если позже загрузите новое фото
через админку, вот тогда ссылка в базе заменится на файл из
Storage (шаг 3).

Проверить: **Table Editor** → `fragrances` — должно быть 23 строки.

## 5. Создать вход для администратора

Публичной регистрации на сайте нет и не будет — только вы можете войти.

1. Слева: **Authentication** → **Users** → **Add user** → **Create new user**.
2. Указать свой email и пароль. **Auto Confirm User** — включить (иначе
   потребуется подтверждение по почте, что не нужно для одного
   администратора).
3. Создать.

Это и есть логин/пароль для входа на `/admin.html`.

## 6. Взять ключи проекта

1. Слева: **Settings** (шестерёнка) → **API**.
2. Скопировать:
   - **Project URL** (выглядит как `https://xxxxxxxx.supabase.co`)
   - **anon public** key (длинная строка в разделе Project API keys)
3. Открыть файл `js/supabase-config.js` в проекте и вписать оба
   значения:

   ```js
   window.SUPABASE_URL = "https://xxxxxxxx.supabase.co";
   window.SUPABASE_ANON_KEY = "eyJhbGciOi...";
   ```

   **Не путайте** `anon public` с `service_role` — второй ключ
   секретный, его в этот файл вставлять нельзя и вообще нигде в коде
   сайта он не должен появляться.

4. Сохранить файл, обновить сайт в браузере (`index.html`) и
   `admin.html`.

## 7. Проверить

- Открыть `admin.html`, войти email/паролем из шага 5.
- Должен появиться список из 23 товаров.
- Изменить цену любого товара → Сохранить → обновить `index.html` в
  соседней вкладке → цена на витрине должна быть новой.
- Так же проверить: добавление нового товара, удаление, загрузку
  нового фото, переключение «В наличии» / «Под заказ».

## Если что-то не работает

- **Каталог на сайте пустой / не меняется** — откройте консоль
  браузера (F12 → Console) на `index.html`, там будет предупреждение
  от Supabase с причиной (обычно — не тот URL/ключ, или таблица
  ещё не создана).
- **Не получается войти в админку** — проверьте, что пользователь
  создан именно в Authentication → Users, и что "Auto Confirm User"
  был включён при создании.
- **Фото не загружается** — проверьте, что бакет называется ровно
  `fragrance-photos` и отмечен как Public.

## Важно про безопасность

- `anon` ключ — не секрет, это нормальная практика Supabase, данные
  защищены через RLS (Row Level Security), а не через секретность
  ключа: читать может кто угодно, а изменять — только тот, кто вошёл
  через Supabase Auth.
- `service_role` ключ (секретный, с полным доступом в обход RLS) в
  этом проекте нигде не используется и не должен попадать ни в один
  файл сайта.
